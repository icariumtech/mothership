# Plan 23-06.2 Summary: Security hardening + healthcheck wiring

## What Was Built

Addressed three remaining code review issues (CR-02, WR-03, WR-04) to make the container image safe to run anywhere and eliminate the mcp service crash-loop on first boot.

### Task 1: config/settings.py — Hardened security defaults

**Before:**
```python
import os
SECRET_KEY = os.environ.get('SECRET_KEY', 'django-insecure-l_lzruv)tsb8...')  # insecure fallback
DEBUG = os.environ.get('DEBUG', 'True') == 'True'   # defaults to debug mode
ALLOWED_HOSTS = os.environ.get('ALLOWED_HOSTS', '*').split(',')  # wildcard
```

**After:**
```python
import os
import sys
SECRET_KEY = os.environ.get('SECRET_KEY')
if not SECRET_KEY:
    print("FATAL: SECRET_KEY environment variable is required", file=sys.stderr)
    sys.exit(1)
DEBUG = os.environ.get('DEBUG', 'False') == 'True'  # safe default
ALLOWED_HOSTS = os.environ.get('ALLOWED_HOSTS', 'localhost,127.0.0.1').split(',')  # loopback only
```

A bare `docker run` without env vars now exits 1 immediately with a clear error message instead of serving Django with a known secret key in debug mode with wildcard host validation. Homelab docker-compose.yml (which sets all three vars) is unaffected.

### Task 2: docker-compose.yml — Healthcheck + service_healthy dependency

**Before:** No healthcheck on `app`; mcp used short-form `depends_on: [app]` (start-only, no readiness wait).

**After:**
```yaml
app:
  healthcheck:
    test: ["CMD", "python3", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/api/active-view/')"]
    interval: 10s
    timeout: 5s
    retries: 5
    start_period: 15s

mcp:
  depends_on:
    app:
      condition: service_healthy
```

The mcp service now waits until gunicorn + Django are fully serving HTTP before starting. This eliminates the httpx connection errors that caused crash-looping on first boot. `ALLOWED_HOSTS` compose default also updated to match settings.py (`localhost,127.0.0.1`).

### Task 3: Dockerfile — BUILD_SECRET_KEY ARG for collectstatic

**Before:** `RUN python manage.py collectstatic --noinput` would fail with the hardened settings.py since no SECRET_KEY is set at build time.

**After:**
```dockerfile
ARG BUILD_SECRET_KEY=django-build-only-not-used-at-runtime
...
RUN SECRET_KEY=$BUILD_SECRET_KEY python manage.py collectstatic --noinput
```

The throwaway ARG value is build-time only — not persisted in image ENV, invisible at runtime. The real runtime SECRET_KEY is always supplied via docker-compose.yml environment.
