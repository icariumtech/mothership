# Phase 24: JANUS Skills — Claude Code skill library for AI-driven campaign data management - Context

**Gathered:** 2026-05-18
**Status:** Ready for planning

<domain>
## Phase Boundary

Create the `janus-skills` GitHub repository — a collection of Claude Code skill `.md` files that encode the JANUS data directory schema into focused, task-specific AI workflows. Skills use the JANUS MCP server (port 8001) to read and write campaign YAML data. The repo ships with an install script supporting both global and project-local installation, and a Claude Code MCP config template.

This phase delivers:
1. `janus-skills` repo with 8 skill files under `skills/`
2. Split schema resources under `resources/` — one file per data domain, each consumed only by the skills that need it
3. `install.sh` — supports `--global` (→ `~/.claude/skills/`) and `--project <path>` (→ `<path>/.claude/skills/`)
4. MCP config template (`mcp-config-template.json`) + `install.sh` optionally writes it to target project's `.claude/settings.json`
5. README with setup instructions

Out of scope: additional MCP tools on the server side (Phase 23 tools are sufficient for v1), automated scheduling/triggers, CI for the skills repo itself.

</domain>

<decisions>
## Implementation Decisions

### Skill Structure
- **D-01:** Separate skill per operation — one `.md` file per skill. Not an umbrella skill with subcommands.
- **D-02:** All skills use the `janus-` prefix (e.g., `/janus-add-npc`, `/janus-generate-context`). Consistent with GSD's `gsd-*` namespace convention and avoids conflicts with other installed skills.
- **D-03:** Skills follow the established Claude Code skill pattern: YAML frontmatter (`name`, `description`, `allowed-tools`) + `<objective>` + `<process>` sections.

### Schema Bundling
- **D-04:** DATA_DIRECTORY_GUIDE is split into topic-specific resource files — each skill @-includes only the slice it needs. No skill loads the full guide.
- **D-05:** Resource files live in `resources/` within the janus-skills repo:
  - `schema-campaign.md` — crew, NPCs, corporation, standby (data/campaign/)
  - `schema-galaxy.md` — star_map, system_map, orbit_map, location hierarchy (data/galaxy/)
  - `schema-ships.md` — ship location.yaml, slug-pointer model, orbit self-registration
  - `schema-encounters.md` — deckplan, rooms, doors, POIs (used by add-location, add-body)
  - `schema-janus-context.md` — janus.yaml format (generated by generate-context skill)
- **D-06:** Resource files are condensed summaries — file paths, YAML field names, naming conventions, required vs optional fields. Not full copies of DATA_DIRECTORY_GUIDE sections.
- **D-07:** Skills can also call `get_data_schema()` MCP tool at runtime for edge cases, but this is a fallback — not the primary knowledge source.

### Installation
- **D-08:** `install.sh` supports two modes:
  - `./install.sh --global` — symlinks all skills to `~/.claude/skills/`
  - `./install.sh --project <path>` — symlinks all skills to `<path>/.claude/skills/`
  - Optional `--mcp-config` flag writes the MCP server config to the target project's `.claude/settings.json` (prompts for server IP)
- **D-09:** Symlinks (not copies) so updating janus-skills repo automatically updates installed skills.

### MCP Config
- **D-10:** `mcp-config-template.json` in repo root shows the Claude Code MCP server config block. `install.sh --mcp-config` optionally injects it into the target `.claude/settings.json`. User provides their homelab server IP during install.

### MVP Skill Set (v1 — 8 skills)
- **D-11:** `/janus-generate-context` — takes location path + notes/text, reads existing location.yaml via MCP, writes `janus.yaml` for the location. Core skill for Obsidian→JANUS pipeline.
- **D-12:** `/janus-add-npc` — creates `data/campaign/npcs/[id].yaml`. Schema: id, name, faction, role, description, stats, location, status.
- **D-13:** `/janus-add-location` — creates a location directory in the galaxy tree with `location.yaml`. Handles slug derivation, type, parent path, description.
- **D-14:** `/janus-session-prep` — calls `get_session_context()`, reads relevant `janus.yaml` files for current location, produces a structured GM session brief.
- **D-15:** `/janus-add-system` — adds a star system to `star_map.yaml` (coordinates, connections, routes) and creates the system directory with `system_map.yaml` + `location.yaml`.
- **D-16:** `/janus-add-body` — adds a planet, moon, or orbital station to an existing system. Updates `system_map.yaml` + `orbit_map.yaml` + creates `location.yaml`.
- **D-17:** `/janus-add-ship` — registers a new ship in `data/ships/` with `location.yaml` (body_slug, system_slug for orbit injection). Optional deckplan stub.
- **D-18:** `/janus-update-galaxy` — edits `star_map.yaml` for nebulae, travel routes, and star system visual properties. The "galaxy painter" skill.

### Claude's Discretion
- Exact YAML field ordering and comment style within generated files
- Whether install.sh uses symlinks or copies (symlinks recommended but script can offer both)
- Exact structure of the MCP config template (follow whatever Claude Code's current `mcpServers` format expects)

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `mcp_server.py` MCP tools: `read_file(path)`, `write_file(path, content)`, `list_files(dir)`, `get_session_context()`, `get_data_schema()` — all skills should route through these, not call Django directly
- `data/galaxy/anchor-system/veil-station/janus.yaml` — canonical example of what `/janus-generate-context` produces

### Established Patterns
- Skill YAML frontmatter: `name`, `description`, `argument-hint`, `allowed-tools` — follow gsd-add-tests pattern exactly
- GSD skill `@`-includes for execution context (e.g., `@$HOME/.claude/get-shit-done/workflows/...`) — janus-skills resources use the same mechanism with relative paths
- `janus-` prefix for all skills — analogous to `gsd-` prefix on GSD skills

### Integration Points
- Skills connect to JANUS via MCP at `http://<server-ip>:8001/mcp/` — configured in `.claude/settings.json` `mcpServers` block
- All file paths passed to MCP tools are relative to `data/` (e.g., `campaign/npcs/foo.yaml`, not `/app/data/campaign/npcs/foo.yaml`)
- Write operations trigger SSE broadcast automatically (D-10 from Phase 23)

</code_context>

<specifics>
## Specific Ideas

- The core motivation is context efficiency: each skill loads only the schema slice it needs, not the full DATA_DIRECTORY_GUIDE. This keeps AI context lean during campaign management operations.
- janus-skills is a standalone repo (`github.com/icariumtech/janus-skills`) — separate from janus-console and janus-deploy.
- Install script uses symlinks so updates to janus-skills propagate automatically to installed locations.

</specifics>
