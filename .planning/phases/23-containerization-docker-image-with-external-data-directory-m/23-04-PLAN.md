<objective>
Create mcp_server.py — the FastMCP HTTP server that exposes five named tools to the campaign AI over HTTP transport on port 8001.

Purpose: The MCP server is the campaign AI's interface to the game. It delegates all logic to the Django REST API (Plan 03) over Docker's internal network. The AI connects to http://homelab-ip:8001/mcp/ and calls tools by name — no direct Django REST API calls needed. This clean separation means the MCP layer is a thin protocol adapter only; all business logic stays in Django views.

Output: New mcp_server.py at project root, runnable as "python mcp_server.py" or via the docker-compose mcp service command.

FastMCP package (fastmcp==3.3.1):
  from fastmcp import FastMCP
  mcp = FastMCP("ServerName")
  @mcp.tool decorator — registers an async function as an MCP tool
  mcp.run(transport="http", host="0.0.0.0", port=8001) — starts HTTP server
  MCP endpoint URL: http://host:8001/mcp/ (FastMCP serves at /mcp/ by default)

Django REST API endpoints (created by Plan 03 — must exist before this plan runs):
  GET  http://app:8000/api/gm/session-context     — returns JSON game state snapshot
  GET  http://app:8000/api/gm/data/?dir={path}    — returns JSON list of filenames
  GET  http://app:8000/api/gm/data/{filepath}     — returns raw YAML text
  PUT  http://app:8000/api/gm/data/{filepath}     — writes YAML, triggers SSE; body = raw YAML string
  GET  http://app:8000/api/gm/data-schema         — returns text/markdown DATA_DIRECTORY_GUIDE.md

httpx (httpx>=0.27.0):
  async with httpx.AsyncClient() as client:
      r = await client.get(url, params={...})
      r = await client.put(url, content=body_str, headers={"Content-Type": "application/x-yaml"})
      r.raise_for_status()  — raises httpx.HTTPStatusError on 4xx/5xx
      r.json()              — parse JSON body
      r.text                — raw text body

Create mcp_server.py at the project root. This is the first async Python file in the project — do not add any synchronous Django imports or settings.

Module-level setup:
  Import: import httpx, import os
  Import: from fastmcp import FastMCP
  Constant: DJANGO_BASE_URL = os.environ.get("DJANGO_BASE_URL", "http://app:8000")
    The env var fallback allows local testing against a running Django dev server by setting DJANGO_BASE_URL=http://localhost:8000.
  Instantiate: mcp = FastMCP("MothershipGM")

Five tools — each decorated with @mcp.tool, each async, each uses httpx.AsyncClient:

Tool 1 — get_session_context():
  Docstring: "Return current game state snapshot: active encounter, tokens, room visibility, ship status, NPC list."
  Calls: GET {DJANGO_BASE_URL}/api/gm/session-context
  Returns: r.json() (dict)

Tool 2 — list_files(dir: str):
  Docstring: "List files in a data directory. dir is relative to data/ (e.g. 'campaign/crew')."
  Calls: GET {DJANGO_BASE_URL}/api/gm/data/ with params={"dir": dir}
  Returns: r.json() (list)

Tool 3 — read_file(path: str):
  Docstring: "Read raw YAML content of a campaign file. path is relative to data/ (e.g. 'campaign/ship/ship.yaml')."
  Calls: GET {DJANGO_BASE_URL}/api/gm/data/{path}
  Returns: r.text (str)

Tool 4 — write_file(path: str, content: str):
  Docstring: "Write YAML content to a campaign file. Triggers SSE broadcast to player terminals. content must be valid YAML."
  Calls: PUT {DJANGO_BASE_URL}/api/gm/data/{path}
         Body: content (raw string), headers={"Content-Type": "application/x-yaml"}
  Returns: r.json() (dict with {"ok": True, "path": ...} on success)

Tool 5 — get_data_schema():
  Docstring: "Return the DATA_DIRECTORY_GUIDE summary so the AI understands the campaign file structure and what files exist."
  Calls: GET {DJANGO_BASE_URL}/api/gm/data-schema
  Returns: r.text (str — markdown content)

Entry point:
  if __name__ == "__main__":
      mcp.run(transport="http", host="0.0.0.0", port=8001)

No Django settings, no manage.py, no synchronous code. This file is standalone Python — it only needs the fastmcp and httpx packages at runtime. The docker-compose mcp service runs it as: command: ["python", "mcp_server.py"].

Do NOT use r.raise_for_status() silently — wrap each httpx call in a try/except block or let raise_for_status() propagate naturally (FastMCP will surface the httpx.HTTPStatusError as a tool error to the calling AI). Per RESEARCH.md Pattern 4, raise_for_status() after every GET/PUT call is correct — FastMCP handles the error reporting to the client.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Campaign AI → mcp_server.py (port 8001) | Remote AI sends tool calls over HTTP; MCP handles session/protocol; tool args are AI-supplied strings |
| mcp_server.py → Django app (http://app:8000) | Internal Docker network call; Django enforces path traversal and YAML validation on write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-04-01 | Tampering | write_file path parameter from AI | mitigate | Django's api_gm_data_file enforces is_relative_to(data_root) and .yaml/.yml extension check — MCP is a passthrough, Django is the enforcement point |
| T-23-04-02 | Tampering | write_file content parameter (malformed YAML) | mitigate | Django's safe_write_yaml() calls yaml.safe_load() before write — invalid YAML returns 400 and MCP surfaces as tool error |
| T-23-04-03 | Information Disclosure | get_session_context exposes all game state to AI | accept | Trust-network model (D-09); AI is the intended consumer of this data; container is homelab-only |
| T-23-04-04 | Denial of Service | AI floods write_file with rapid requests | accept | Homelab context; no rate limiting per D-09; Django's atomic write is the only guard needed |
</threat_model>
