Create Dockerfile at the project root with two stages.

Stage 1 (Node — builds Vite frontend):
  FROM node:22-slim AS frontend-builder
  WORKDIR /build
  RUN corepack enable
  Copy package.json and pnpm-lock.yaml first (cache layer), then RUN pnpm install --frozen-lockfile
  Copy src/, vite.config.ts, tsconfig.json
  RUN pnpm run build
  Output lands at /build/core/static/js/ per vite.config.ts outDir setting

Stage 2 (Python — Django production image):
  FROM python:3.12-slim AS app
  WORKDIR /app
  Set ENV: PYTHONDONTWRITEBYTECODE=1, PYTHONUNBUFFERED=1, DJANGO_SETTINGS_MODULE=config.settings
  Copy requirements.txt, RUN pip install --no-cache-dir -r requirements.txt
  COPY . . (copies all Django source)
  COPY --from=frontend-builder /build/core/static/js/ core/static/js/ (overwrites with built assets)
  RUN python manage.py collectstatic --noinput (runs during BUILD, not at runtime — per anti-pattern in RESEARCH.md)
  COPY docker-entrypoint.sh /docker-entrypoint.sh
  RUN chmod +x /docker-entrypoint.sh
  EXPOSE 8000
  ENTRYPOINT ["/docker-entrypoint.sh"]

Key details:
  - collectstatic runs during docker build, not at startup. Running it at startup adds latency on every restart.
  - The COPY . . step copies the existing (empty/dev) core/static/js/. The subsequent COPY --from=frontend-builder overwrites it with built assets. Order matters.
  - DJANGO_SETTINGS_MODULE must be config.settings — not mothership.settings.
  - The Python stage does NOT run gunicorn — that is done by docker-entrypoint.sh at container start.
  - No CMD is set — docker-entrypoint.sh is the ENTRYPOINT and handles the default command internally.

  <action>
Create docker-entrypoint.sh at the project root with these behaviors:

1. #!/bin/bash and set -e at top

2. Print startup banner: echo "=== MOTHERSHIP ENTRYPOINT ==="

3. Always run: python manage.py migrate --noinput
   This is safe on an already-migrated database (idempotent). Do NOT check for db.sqlite3 existence — Docker bind mounts create missing files as directories (Pitfall 5). Always running migrate avoids the check entirely.

4. Optional superuser creation:
   if [ -n "$DJANGO_SUPERUSER_USERNAME" ] && [ -n "$DJANGO_SUPERUSER_PASSWORD" ]; then
     python manage.py createsuperuser --noinput \
       --username "$DJANGO_SUPERUSER_USERNAME" \
       --email "${DJANGO_SUPERUSER_EMAIL:-admin@localhost}" \
       2>/dev/null || echo "Superuser already exists, skipping."
   fi
   
   Uses Django's native --noinput env var support: DJANGO_SUPERUSER_USERNAME, DJANGO_SUPERUSER_PASSWORD, DJANGO_SUPERUSER_EMAIL. No custom management command needed per D-06.

5. CMD override guard (CRITICAL — prevents mcp service from running migrations):
   if [ "$#" -gt 0 ]; then
     exec "$@"
   fi
   
   When docker-compose specifies command: ["python", "mcp_server.py"], those args are passed as "$@" to the entrypoint. The guard execs them directly, skipping migrate and createsuperuser. The mcp service must NOT run migrations (Pitfall 6 — race condition with app service).

6. Default path (no CMD override):
   echo "=== Starting Gunicorn ==="
   exec gunicorn --config gunicorn.conf.py config.wsgi:application
   
   Uses config.wsgi:application (not mothership.wsgi) per PATTERNS.md WSGI Module Path section.

After creating the file, ensure it is executable: the Dockerfile runs chmod +x on it, but also set the git executable bit locally.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| docker-compose env → entrypoint | DJANGO_SUPERUSER_PASSWORD sourced from compose environment; must not be logged |
| Dockerfile build → final image | No secrets baked in; SECRET_KEY only at runtime via env |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-02-01 | Information Disclosure | DJANGO_SUPERUSER_PASSWORD in entrypoint | mitigate | Value comes from env var only; 2>/dev/null on createsuperuser suppresses any echo of credentials |
| T-23-02-02 | Elevation of Privilege | mcp service running migrations races app | mitigate | CMD override guard (if [ "$#" -gt 0 ]) — mcp service command bypasses migrate entirely |
| T-23-02-03 | Denial of Service | db.sqlite3 mounted as directory (Pitfall 5) | accept | Document in README: run `touch db.sqlite3` on host before first `docker compose up`; error message from SQLite is clear |
</threat_model>
