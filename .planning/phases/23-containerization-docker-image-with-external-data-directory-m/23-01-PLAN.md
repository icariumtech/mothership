Part A — gunicorn.conf.py (new file at project root):
Create gunicorn.conf.py with these exact settings:
  workers = 1
  worker_class = 'gevent'
  worker_connections = 500
  bind = '0.0.0.0:8000'
  timeout = 0
  max_requests = 1000
  max_requests_jitter = 100
  accesslog = '-'
  errorlog = '-'
  loglevel = 'info'

  def post_fork(server, worker):
      from gevent import monkey
      monkey.patch_all()

Set workers = 1 (not 3) per RESEARCH.md recommendation for homelab. The broadcaster is a per-process singleton — multiple workers would prevent SSE events from reaching all clients when a write lands on a different worker than the SSE subscriber. workers=1 with gevent greenlets handles ~5 concurrent players easily (500 worker_connections headroom).

Set timeout = 0 because with gevent workers, the master process cannot distinguish a sleeping greenlet (SSE waiter doing queue.get(timeout=30)) from a hung one. A finite timeout kills SSE connections.

The post_fork hook applies gevent monkey-patching in the worker process before any Django code executes. If patching happens after Django's ORM initializes its DB connections, SQLite throws "DatabaseWrapper objects created in a thread can only be used in that same thread".

Part B — core/sse_broadcaster.py (add announce_generic method):
Add the announce_generic method to the MessageAnnouncer class after the announce_ship_status method. Replicate the exact structure of announce_ship_status, parameterized on event name:

  def announce_generic(self, event: str, data: dict) -> None:
      """Broadcast a named SSE event with arbitrary data to all connected clients."""
      msg = format_sse(json.dumps(data, default=str), event=event)
      with self._lock:
          listeners = list(self.listeners)
      for i in reversed(range(len(listeners))):
          try:
              listeners[i].put_nowait(msg)
          except queue.Full:
              self.unlisten(listeners[i])

This method is called by the YAML write API endpoint (Plan 02) after a successful file write per D-10. The try/except isolation is handled in the calling view, not in announce_generic itself.
