<objective>
Fix two interlinked deployment blockers preventing the Phase 23 container image from being built and deployed safely:

1. **VERIFICATION GAP (BLOCKER):** `Dockerfile` references `pnpm-lock.yaml` which does not exist in the repository. The project uses npm (`package-lock.json` is present, `lockfileVersion: 3`). `docker build` fails immediately at the `COPY package.json pnpm-lock.yaml ./` step, so no image can ever be published to GHCR.

2. **CR-01 (CRITICAL):** `docker-entrypoint.sh` unconditionally runs `python manage.py migrate --noinput` BEFORE the CMD-override guard (`if [ "$#" -gt 0 ]; then exec "$@"; fi`). The mcp service — which is supposed to bypass Django setup — therefore still triggers a Django migration against the same bind-mounted SQLite database that the app service is also migrating. This causes `OperationalError: database is locked` and (because `set -e` is active) kills the mcp container at startup.

Purpose: Without these fixes, `docker compose up` cannot succeed on the homelab even if every other phase 23 deliverable is correct. The GHCR image cannot be built, and even if it could, the mcp service would crash-loop.

Output: A buildable Dockerfile that produces a working image, and an entrypoint script whose CMD guard runs first so the mcp service skips Django entirely.
</objective>
