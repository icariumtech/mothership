- [ ] CONSTRAINT: POI_ROOM_SCOPE — POIs are room-scoped in YAML (under room.poi[]). buildPoiRoomMoveEdit handles cross-room moves atomically; do not revert to buildPositionEdit for onPoiMove.
- [ ] CONSTRAINT: POINTER_VS_MOUSE — stopPropagation on pointer events does NOT cancel React synthetic mouse events. Use closest() guards in usePanZoom for any new draggable elements.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| GM_HIT_TARGETS | EncounterMapRenderer renders room hit elements in two branches: isGM and !isGM. New pointer callbacks must be added to BOTH. Discovered when room click-to-jump silently did nothing in GM mode. | blocking | Before wiring any new pointer callback, grep for `isGM ?` in room render functions and confirm GM branch also has the new handler. |
| POI_DRAG_CLICK_LEAK | After pointerup ending a drag, browser fires a click event on whatever element is under the cursor. Without suppression this triggers handleSvgBackgroundClick → onEmptyCellClick, creating a spurious New POI. | blocking | Use poiJustDroppedRef — set true on drag-end in document pointerup, check+clear in handleSvgBackgroundClick. Already implemented. |
| ROOM_LEVEL_POI_NORMALIZATION | Frontend deckToMapData did not lift room-level poi[] entries to top-level, unlike backend normalize_deck_poi. New POI features must account for both room-level and deck-level poi in the YAML. | advisory | normalizeClientPoi() in useDeckplanModel.ts is the client-side equivalent. Keep in sync with backend logic. |
