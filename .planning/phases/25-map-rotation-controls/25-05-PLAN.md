<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: GM smoke test — galaxy, system, orbit map playback controls</name>
  <what-built>
    Phase 25 ships:
    - `MapPlaybackControls` overlay component (top-center pill with play/pause + optional scrub bar)
    - Galaxy map: ⏸/▶ button toggling sceneStore.animations.autoRotate (no scrub bar)
    - System map: ⏸/▶ + horizontal scrub bar that scrubs planet orbital positions when paused
    - Orbit map: ⏸/▶ + horizontal scrub bar that scrubs moon/orbital-station positions when paused
  </what-built>
  <how-to-verify>
    Bring up the dev server if not running:
    1. From project root: `./start_server.sh` (Django) and `pnpm run dev` (Vite) — typically already covered by the start script.
    2. Open the GM Console at http://localhost:8000/gmconsole/ in a desktop browser. (Touch-TV-specific verification can be deferred unless the user wants to test on the actual TV.)

    Galaxy map verification:
    3. Click the BRIDGE view in the left rail. Click the MAP tab in the bridge header (should default to galaxy).
    4. Confirm: a small overlay pill is visible at top-center of the map, containing only a ⏸ button (no scrub bar). Border color is muted teal-ish.
    5. Click the ⏸ button. The galaxy auto-rotation stops. The button now displays ▶ and its border turns amber.
    6. Wait 10 seconds. The galaxy should NOT resume rotating automatically. (This is the 5s auto-resume gotcha — if rotation resumes, recordInteraction was incorrectly called in Plan 02.)
    7. Click ▶. The galaxy resumes rotating.

    System map verification:
    8. Use the LOCATIONS panel (tool rail) to navigate to a system view (e.g., Tau Ceti).
    9. Confirm: overlay pill shows ⏸ + a horizontal scrub bar to its right. While playing, scrub track is gray and no thumb is shown; cursor over the scrub is default.
    10. Click ⏸. Planets freeze. Button becomes ▶ with amber border. Scrub track turns teal; an amber thumb appears.
    11. Click and drag the scrub bar to the right. Planets should advance along their orbits in real time (one or more visible).
    12. Drag back to the left. Planets reverse.
    13. Click a planet to select it. Drag scrub again — the speed should now feel calibrated to that planet's orbital period (slower for outer planets).
    14. Click ▶. Orbits resume animating from their current scrubbed angle (no jump-back to live time — or if SUMMARY for Plan 03 documents that the simpler reset-to-live behavior was chosen, planets snap back to where they would be in live time; either is acceptable per D-07).

    Orbit map verification:
    15. Click on a planet that has a deck/orbit view (e.g., a habitable body in Tau Ceti). Confirm the orbit view opens with moons/orbital stations.
    16. Repeat steps 9-13 with moons + stations. Confirm orbital freeze + scrub direction.
    17. Independent of the play/pause button: click a surface marker on the planet body. Existing behavior should still freeze moon/station animation while the marker is selected (this is the existing `animationPaused` flow — must remain functional).

    Visual check:
    18. Confirm the overlay pill does NOT occlude critical labels or controls in any view. If it does, document the position issue but the spec value (top: 24px) is the agreed default.
    19. Confirm the button is at least 44x44 px (TV touch target). Browser devtools → measure if uncertain.

    Report any deviations from the above. "approved" means all 19 steps pass cleanly with no deviations from expected behavior.
  </how-to-verify>
  <acceptance_criteria>
    - GM has run all 19 steps
    - Galaxy auto-resume gotcha is verified absent (step 6)
    - System scrub direction is correct (right=forward, left=reverse, step 11-12)
    - Orbit scrub works AND surface marker selection still freezes independently (step 17)
    - GM signals "approved" or documents specific deviations
  </acceptance_criteria>
  <resume-signal>Type "approved" once all 19 verification steps pass, or describe specific failures/deviations.</resume-signal>
