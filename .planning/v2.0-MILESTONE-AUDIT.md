## Unsatisfied / Partial Requirements

### D-10 (Phase 23) — SSE broadcast after PUT write → player terminal update

**Status:** PARTIAL  
**Phase:** 23-containerization  
**Description:** After every PUT to `/api/gm/data/{path}`, the backend calls `broadcaster.announce_generic('data-changed', ...)`. The backend half is implemented and verified. However, the frontend `src/hooks/useSSE.ts` only registers listeners for `activeview` and `shipstatus` events — there is no `data-changed` listener anywhere in the codebase.

**Impact:** When the GM edits a YAML file via `FileEditorView` (Phase 28) and saves, the Django backend broadcasts a `data-changed` SSE event to all connected clients. Player terminals receive the SSE message but silently discard it — `SharedConsole.tsx` never acts on it. Players must manually switch views to pick up updated data.

**Evidence:**
- `core/views/gm_data.py` lines 238, 279, 298, 356, 433 — `announce_generic('data-changed', ...)` fires correctly
- `src/hooks/useSSE.ts` — only `activeview` (line 46) and `shipstatus` (line 55) listeners
- No `es.addEventListener('data-changed', ...)` anywhere in the frontend codebase

**Fix:** Add a `data-changed` listener in `useSSE.ts` (or a new hook) that triggers a data reload in the player terminal when the event fires. The response payload includes `{path, event}` — a selective re-fetch based on `path` would be ideal.
