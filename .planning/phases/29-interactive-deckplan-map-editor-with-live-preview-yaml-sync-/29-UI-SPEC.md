| Token | Value | Usage |

| sm | 8px | Toolbar gaps, deck-tab padding-y, compact control spacing |
| md | 16px | Toolbar horizontal padding, panel section padding |

## Layout & Interaction Contract

This section supplements the template to capture phase-specific structural decisions from `29-CONTEXT.md` (D-07 through D-15) and `29-RESEARCH.md`, since the editor surface is new.

### Preview pane placement (D-07, D-08)
- Mounts **below Monaco** inside `.gm-file-editor-view__editor-area`, only when `isDeckplan(selectedPath)` is true.
- Split orientation: vertical stack — Monaco on top, preview pane below.
- Default split ratio: **60/40** (Monaco/preview) — Claude's discretion exercised toward giving the preview enough room to be useful for clicking small rooms/POIs, while keeping Monaco dominant for text editing.
- Resizable: yes, via a horizontal drag handle between the two panes (4px visual / 44px hit target per Spacing Scale exceptions). Persist the split ratio in `localStorage` alongside `LS_KEY` (same pattern as last-opened-path).
- Preview pane background: `#080e0e` (dominant), separated from Monaco by a 1px `#1e3333` border (matches existing `.gm-file-editor-view__error-banner` border-bottom convention).

### Deck selector (D-08)
- Form: **horizontal tab strip** (Ant Design `Tabs` with `type="card"` styled to match the monospace/chamfer aesthetic, or a custom `Segmented`-style row of buttons) — Claude's discretion resolved toward tabs because deck counts are small (1-4 typically) and tabs read clearly as "which deck am I viewing."
- Position: top edge of the preview pane, height 32px, background `#0d1616` (secondary), bottom border `#1e3333`.
- Tab label: deck `name` (or `id` uppercased fallback), Label typography (11px/600/uppercase/1px letter-spacing).
- Active tab: amber (`#c9a050`) text + 2px amber bottom-border indicator. Inactive tabs: `#4a7070` text, no indicator, hover → `#7ab8b8`.
- Selection persistence: keyed by deck `id` per Pitfall 1 in RESEARCH.md — if the previously-selected id disappears after a re-parse, fall back to the `default: true` deck, else `decks[0]`.

### Map preview rendering
- Reuses `<MapPreview>` with `fill={true}` (fills the preview pane), `isGM={true}`, `roomVisibility={{}}` (editor doesn't track runtime reveal state — all rooms always visible in the editor).
- Pan/zoom: inherited from `MapPreview` unchanged.

### Click-to-jump (EDIT-04, D-09)
- Click a room or POI on the preview → `editor.revealRangeInCenter()` + `editor.deltaDecorations()` on the matching deck-scoped `id:` line in Monaco.
- Highlight styling (Claude's discretion): `inlineClassName` applies `background: rgba(201, 160, 80, 0.18)` (amber at 18% opacity) with `border-left: 2px solid #c9a050`, full-line (`isWholeLine: true`). Decoration persists until the next click-to-jump or until the user moves the caret manually (whichever first) — do not auto-clear on a timer (GM needs time to read the YAML).
- Cursor on hover over clickable rooms/POIs in the preview: `pointer`.

### POI drag-to-move (EDIT-05, D-10, D-12)
- Drag affordance: while dragging, the POI icon gets a 2px amber (`#c9a050`) outline/glow (reuse the existing token-drag visual pattern from `TokenLayer`, recolored from its current color to amber to signal "editor mode" vs. "runtime token mode").
- Drop: on pointer-up, surgically replace the `position:` value span with `{x: <newX>, y: <newY>}` (Pattern 3 from RESEARCH.md). No confirmation dialog — this is a low-stakes, instantly-visible, undoable-via-Ctrl+Z text edit.
- Drag-vs-click threshold: 5px (matches `TokenLayer`'s `DRAG_THRESHOLD`).

### Click-to-add POI (EDIT-06, D-11)
- Click an empty grid cell (no room/POI under cursor) → insert a POI stub at that cell's `{x, y}` into the selected deck's `poi:` list (create the list if absent), using default values: `name: "New POI"`, `type/icon: "marker"`.
- Visual feedback on insert: the newly-added POI renders immediately in the preview (buffer-driven, per "live" requirement) AND triggers a click-to-jump highlight on the newly-inserted YAML lines (same amber highlight as EDIT-04) so the GM immediately sees what text was added and can edit `name`/`type`/`icon` themselves (text-only per D-13).
- No "are you sure" — click-to-add is reversible via Ctrl+Z and is explicitly the cheap/fast authoring path this phase exists to provide.

### Parse-error resilience (Pitfall 2)
- On YAML parse failure during active typing: keep showing the **last successfully-parsed preview** (do not blank it), debounce re-parse ~200ms. Only show the `NO PREVIEW AVAILABLE` empty state if the **very first** parse attempt for a newly-opened deckplan fails (i.e., the file was already invalid YAML when opened) — in all other cases, a stale-but-rendered preview is better than blanking.
