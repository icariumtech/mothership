# Plan 23-06.1 Summary: Dockerfile npm fix + entrypoint CMD guard reorder

## What Was Built

Fixed two interlinked deployment blockers preventing the Phase 23 container image from building and running safely.

### Task 1: Dockerfile — pnpm → npm

**Before:**
```dockerfile
# used corepack + pnpm-lock.yaml (which does not exist in the repo)
RUN corepack enable
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile
RUN pnpm run build
```

**After:**
```dockerfile
# uses npm ci against package-lock.json (which does exist)
COPY package.json package-lock.json ./
RUN npm ci
RUN npm run build
```

The project uses npm (`package-lock.json` at lockfileVersion 3). `pnpm-lock.yaml` does not exist. The `COPY package.json pnpm-lock.yaml ./` line caused `docker build` to fail immediately. The `corepack enable` line was also removed (unnecessary for npm).

### Task 2: docker-entrypoint.sh — CMD guard moved before migrate

**Before (broken order):**
1. `python manage.py migrate --noinput`
2. createsuperuser block
3. `if [ "$#" -gt 0 ]; then exec "$@"; fi`  ← too late for mcp service

**After (correct order):**
1. `if [ "$#" -gt 0 ]; then exec "$@"; fi`  ← FIRST — mcp exits here
2. `python manage.py migrate --noinput`
3. createsuperuser block
4. gunicorn

The mcp service uses `command: ["python", "mcp_server.py"]` in docker-compose.yml. Those args arrive as `$@`. Previously, the entrypoint ran `migrate` before checking `$@`, causing both `app` and `mcp` to race against the shared bind-mounted `db.sqlite3`, producing `OperationalError: database is locked` and crashing the mcp container.
