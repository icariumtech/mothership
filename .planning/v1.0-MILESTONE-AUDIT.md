## Integration Findings

### Confirmed Working — E2E Flows

1. **Token placement flow**: GM drags from TokenPalette → `encounterApi.placeToken()` → `update_state()` + `broadcaster.announce()` → SSE `activeview` event → `SharedConsole.onEvent` → `setEncounterTokens()` → `EncounterView` → `TokenLayer` renders token. **Fully wired.**

2. **Portrait display flow**: GM clicks SHOW in EncounterPanel → `encounterApi.togglePortrait()` → `update_state()` → SSE broadcast (includes `encounter_npc_data` embedded) → `SharedConsole.setActiveView()` → `NPCPortraitOverlay` renders cards. **Fully wired.**

3. **Grid map + multi-rect tokens**: `isGridEncounterMap()` routes to `EncounterMapRenderer`; `TokenLayer.findRoomAtCell` tests all rects + polygon + circle shapes via duck-typing. **Fully wired.**

4. **SSE as sole transport**: No remnant `setInterval` for active-view in SharedConsole or GMConsole. Both use `useSSE` hook exclusively. Only remaining intervals: CHARON bridge messages (SharedConsole) and channel unread counts (GMConsole).

### Degraded Flows

5. **Ship status change flow**: GM toggle → `api_ship_toggle_system` → `update_state()` + `broadcaster.announce()` → SSE fires with `ship_system_overrides` field → **nobody consumes it**. `StatusSection` polls `/api/ship-status/` every 3 seconds independently. `ShipStatusPanel` (GM) polls every 5s. Animation works but with up to 3s latency. SSE payload carries dead weight for ship status.

### Notable Cross-Phase Issue

**TokenLayer visibility filter regression** (non-blocking but inconsistent):
- Phase 03 commit `0faa64f`: changed filter to `=== true` (strict — token only visible if room explicitly revealed)
- Phase 07 commit `bdacc0d`: reverted to `!== false` (permissive — tokens visible unless room explicitly hidden)
- Current state: players can **see** tokens in rooms absent from `roomVisibility` dict, but **cannot move** tokens there (move guard at line 222 still uses `!== true`)
- MEMORY.md documents `!== false` as current intended behavior — so the revert appears intentional, but the asymmetry with the move guard is a bug
